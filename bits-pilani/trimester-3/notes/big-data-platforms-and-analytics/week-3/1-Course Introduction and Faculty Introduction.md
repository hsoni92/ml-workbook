# Week 3 – MapReduce Programming Model (Part 1)

## Module Introduction
Based on transcriptions from week 3 recordings, this module covers the foundational MapReduce programming model.

### Background
- Builds on Modules 1-2: hardware constraints, distributed systems principles, CAP theorem
- Focuses on "brain" of distributed processing
- Designed to hide cluster complexity from developers

### Core Concept: Functional Programming Paradigm
- **Map**: Function application across data elements
- **Reduce**: Aggregation/folding operations
- **Pure Functions**: Stateless, deterministic, critical for reliability
- **Immutability**: No side effects in processing logic

### Learning Objectives
- Understand MapReduce as a programming abstraction
- Recognize functional programming principles in big data
- Identify components of the MapReduce execution pipeline
- Appreciate how theory enables practical distributed processing

## Foundational Insights
1. The "brain" concept - coordinating thousands of machines through software
2. Functional programming as the basis for reliable distributed processing
3. Importance of pure functions for fault tolerance
4. Mapping complex cluster operations into simple developer tasks
